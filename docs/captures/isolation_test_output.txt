===== Network isolation WITHOUT Tailscale overlay =====

[1] admin-panel responds within its own namespace (ts-admin-panel:8080)
Error response from daemon: No such container: tailscale-admin-panel-1

[2] rds-sim responds locally with user demo
Error response from daemon: No such container: tailscale-rds-sim-1

[3] eng-operator CANNOT resolve admin-panel via DNS (isolated network tailscale_net-eng-operator)
Error response from daemon: No such container: tailscale-eng-operator-1
   [TIMEOUT - DNS does not resolve, as expected]

[4] eng-operator CANNOT reach admin-panel via direct IP (distinct docker networks)
Error response from daemon: No such container: tailscale-eng-operator-1
   [BLOCKED - expected without tailnet]

[5] eng-operator CANNOT reach rds-sim directly
Error response from daemon: No such container: tailscale-eng-operator-1
   [BLOCKED - expected without tailnet]

===== Conclusion =====
Personas (eng-operator, etc.) CANNOT reach the services directly.
In the full POC with Tailscale running, the tailnet overlay routes between these hosts
using tags and ACLs. The current docker network isolation is the 'sandboxing' that
forces EVERY cross-service hop to traverse Tailscale.
